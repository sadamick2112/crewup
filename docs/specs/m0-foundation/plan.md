# M0 — Foundation: Plan

**Status:** Approved · October 14, 2026 (amended the same day for M0-24, M0-25, and M0-26…M0-28) · Implements `spec.md` (Approved)

## Context

The repo contains only docs. M0 builds the walking skeleton that every later milestone extends: a Spring Boot + Modulith backend and a React SPA, run locally with Docker Compose (Postgres, Keycloak), connected by a generated API client. CI checks build, tests, module boundaries, formatting and linting, and security scans. The demo: sign in through Keycloak, and the home page greets you with data from `GET /api/me`.

This plan fixes the *how*: layout, versions, dependencies (with reasons, per CLAUDE.md), configuration, the sign-in design, CI, and which test proves each criterion.

**Deliberately not the latest:**
- **TypeScript 5.9.3, not 7.0.** TypeScript 7 is the new native (Go) compiler. `typescript-eslint` supports only `<6.1`, and `openapi-typescript` declares `^5.x`. 5.9.3 is the newest version every tool accepts. Revisit when `typescript-eslint` supports 7.
- **ESLint 9.39.5, not 10.** `eslint-plugin-jsx-a11y` (last released 2024) supports ESLint up to 9. Revisit when it supports 10, or when a maintained replacement exists.
- **React Router 8, not 7** (the plan's expected line). 8 is the current major; the routing needs here are basic.
- **Tracing:** `micrometer-tracing-bridge-otel` rather than Boot 4's `spring-boot-starter-opentelemetry`. The starter brings an OTLP exporter, which would try to send traces to a collector that M0 doesn't have. The bridge gives trace IDs in logs with nothing to switch off. Moving to the starter later is a dependency swap.

## 4. Local environment (M0-1, M0-2, M0-14)

- **Ports:** backend 8080, Vite 5173, Keycloak 8180, Postgres 5432 (each overridable in `.env`).
- **One config file:** `.env` (gitignored, copied from `.env.example`) holds DB name/user/password and Keycloak admin credentials. Compose reads it natively. The backend imports it with `spring.config.import: optional:file:../.env[.properties]`, so there's one copy step and no extra library. `application-local.yml` stays available for personal overrides (gitignored; `application-local.example.yml` committed).
- **Keycloak:** `quay.io/keycloak/keycloak:<pinned>` run with `start-dev --import-realm`. Its dev-file store is fine locally; the realm is re-imported from the committed export.
- **Realm `crewup`** (`infra/keycloak/crewup-realm.json`): self-registration on, login with email, verify-email off (dev). Client `crewup-web`: public, standard flow only, PKCE `S256` required, redirect `http://localhost:5173/*`, web origin `http://localhost:5173`, post-logout redirect. An audience mapper adds `crewup-api` to access tokens, and the backend checks it (so tokens issued for other clients are rejected). Dev user `dev@crewup.local` / `dev`. The realm and user descriptions say "DEV ONLY", and so does the README.
- **Health (M0-3):** `/actuator/health` is public and shows components (`db`, `ping`) without details. Only `health` and `info` are exposed.

## 5. Backend design

**Modules (M0-8).** `identity` (owns User) and `shared`. `shared` is marked `@ApplicationModule(type = OPEN)` and holds only cross-cutting types (`Ids` in M0). `ModularityTests` runs `ApplicationModules.of(CrewUpApplication.class).verify()`.

**IDs (JAVA-14).** `app.crewup.shared.Ids.newId()` returns a UUID v7 (48-bit Unix-millisecond timestamp, version and variant bits, random tail), using `SecureRandom`. Entities assign their ID in the constructor, not the database. Unit tests check the version/variant bits and ordering across milliseconds.

**User (M0-6).**
- Table `users` (`user` is reserved in Postgres): `id uuid pk`, `subject text not null unique`, `email text`, `display_name text not null`, `created_at timestamptz not null`, `updated_at timestamptz not null`. Migration `db/migration/identity/V20261014120000__identity_create_users.sql`.
- **Migration numbering:** timestamp versions (`V<yyyyMMddHHmmss>__<module>_<what>.sql`) so migrations from different module folders never collide. Flyway is configured with `spring.flyway.locations: classpath:db/migration/*` (update DB-1 in `coding-standards.md` with this convention).
- `UserProvisioningService.currentUser(Jwt)` (in `@Transactional`): find by `sub`. If found, refresh email/display name when the token's values changed. If not found, create it. A concurrent first call that hits the unique constraint re-reads the existing row, so two simultaneous first calls can't create duplicates or fail.
- Display name: `name` claim, falling back to `preferred_username`, then `email`.
- `MeController`: `GET /api/me` returns `UserProfile(id, displayName, email)`, a record mapped with `UserProfile.from(user)` (JAVA-5).

**Security (M0-4).** A `SecurityFilterChain`:
- stateless sessions, OAuth2 resource server with JWT, `issuer-uri` = `http://localhost:8180/realms/crewup` (from `.env`), plus a `crewup-api` audience validator
- `permitAll` for `/actuator/health`, `/v3/api-docs/**`, `/swagger-ui/**`; `authenticated()` for `/api/**`; deny everything else
- CSRF disabled, with `// nosemgrep: <rule> -- stateless bearer-token API; see ADR-004` (M0-19, spec decision 6)
- a custom `AuthenticationEntryPoint` and `AccessDeniedHandler` that write RFC 9457 `application/problem+json` for 401/403. `spring.mvc.problemdetails.enabled: true` covers MVC errors. The `@RestControllerAdvice` for domain exceptions (JAVA-11) arrives with the first domain exception (M1), not in M0, because nothing would use it yet (GEN-10).

**Logging and tracing (M0-26, M0-27).**
- **Format:** Spring Boot's console pattern (which shows `[traceId-spanId]` once tracing is on) locally. Outside local development, `LOGGING_STRUCTURED_FORMAT_CONSOLE=ecs` switches to ECS JSON with no code change. Root level INFO, `app.crewup` INFO, both overridable by environment variable.
- **Tracing:** Micrometer Tracing with W3C propagation. Sampling is 1.0, which only matters once an exporter exists.
- **Request log line:** `RequestLoggingFilter` (a `OncePerRequestFilter` in `shared`, ordered after the security filters) writes one INFO line per `/api/**` request with key-values `http.method`, `http.route` (the matched pattern, e.g. `/api/me`, not the raw URL), `http.status`, `durationMs`, and `subject` (the JWT `sub`) when authenticated. It never reads query strings, headers or bodies. Health and OpenAPI calls aren't logged.
- **`traceId` in errors:** a small `ProblemDetailsSupport` helper in `shared` adds the current `traceId` to a `ProblemDetail`. The security entry point and access-denied handler use it, and a `ResponseBodyAdvice<ProblemDetail>` applies it to every Problem Details response Spring MVC produces.

**CORS:** none needed in development. Vite proxies `/api` to `localhost:8080`, so the browser sees one origin. Production is decided in M8.

**OpenAPI (M0-9).** springdoc publishes `/v3/api-docs`. `OpenApiContractTest` (a Testcontainers integration test) fetches it and compares it with the committed `api/openapi.json`. Run with `-Dopenapi.update=true`, it rewrites the file instead. CI fails if the contract changed without the file being updated. This is the "OpenAPI diff in CI" from `architecture.md` §9, with no extra plugin.

## 6. Frontend design

- **Scaffold:** Vite `react-ts` template, `strict` TS, path alias `@/` → `src/`. Tailwind 4 through `@tailwindcss/vite`. `shadcn init`, then `shadcn add button card`.
- **Routing:** `/` (home) and `/auth/callback`.
- **Auth (M0-5, M0-7; spec decision 2):** `react-oidc-context` wraps the app. `UserManager` settings: authority `http://localhost:8180/realms/crewup`, client `crewup-web`, response type `code` (PKCE is automatic), `userStore` = in-memory (tokens never in `localStorage` or `sessionStorage`), `automaticSilentRenew: true`.
  - **Staying signed in across reloads (M0-7):** in-memory tokens are lost on reload. At startup the app calls `signinSilent()` (a hidden iframe with `prompt=none`), which uses Keycloak's SSO session cookie to get fresh tokens without a visible redirect. `localhost:5173` and `localhost:8180` are same-site, so the cookie is sent. **M8 note:** production must host the identity provider on the same site (e.g. `auth.<domain>`), or this falls back to a quick redirect; record it in ADR-004.
  - Sign out calls `signoutRedirect()`, which ends the Keycloak session.
  - **Kept thin for testing (TEST-12):** `src/app/auth/oidcConfig.ts` is a plain settings object with no logic. The decisions (try silent sign-in at startup; treat `login_required` or any silent-sign-in error as "signed out" instead of an error screen) live in `restoreSession(userManager)` in `src/app/auth/restoreSession.ts`, covered by the T11 red tests with a fake `UserManager`. What's left untested in jsdom is the provider wiring in `main.tsx` (already excluded) and the config object; if coverage still falls short, the exclusion is proposed for that one file.
- **API client:** `npm run gen:api` runs `openapi-typescript ../api/openapi.json -o src/shared/api/schema.d.ts`. `src/shared/api/client.ts` creates an `openapi-fetch` client with middleware that attaches `Authorization: Bearer <access token>`. Generated files carry a "generated, do not edit" header.
- **Trace correlation (M0-28):** `src/shared/api/traceparent.ts` exports `newTraceparent()`, which returns `{ header, traceId }`, using `crypto.getRandomValues` (`00-<32 hex>-<16 hex>-01`, never all zeros). The `openapi-fetch` middleware sets the header on every request and attaches the `traceId` to any error it throws as `ApiError`. `ErrorMessage` shows "Something went wrong. Reference: {traceId}" and calls `console.error` with the same ID. ESLint `no-console` allows only `warn` and `error` (LOG-7).
- **Server state:** `src/core/me/` holds `meKeys` and `useMe()` (TanStack Query, enabled only when signed in) (TS-5).
- **Home page (M0-7, M0-10, M0-11):** signed out, a shadcn `Button` "Sign in". Signed in, "Hello, {displayName}" in a `Card` plus "Sign out". Mobile-first layout, with no horizontal scroll at 360 px.
- **Scripts:** `dev`, `build`, `preview`, `test` (Vitest), `lint`, `format`, `format:check`, `typecheck` (`tsc -b --noEmit`), `gen:api`, `e2e` (Playwright).

## 7. Security scanning (M0-15 … M0-19)

- **`.github/workflows/security.yml`** (push and PR to `main`):
  - **Semgrep:** the `semgrep/semgrep` container runs `semgrep scan --config p/java --config p/spring --config p/typescript --config p/react --config p/owasp-top-ten --config .semgrep --sarif`. Results upload to code scanning, and `--error` with severity `ERROR` fails the job. A second step runs `semgrep --test .semgrep`.
  - **gitleaks:** the official `ghcr.io/gitleaks/gitleaks` image scans the pushed commit range, plus a full-history scan on `main`. A `.gitleaks.toml` allowlist is used only for the documented dev-only realm values, each with a reason.
- **`.github/workflows/codeql.yml`:** a matrix over `java-kotlin` (build mode `none`) and `javascript-typescript`, with the `security-extended` query suite. The failure threshold ("High or higher") is a repository setting, listed in §9.
- **`.semgrep/` rules,** each with a fixture file (`// ruleid:` / `// ok:` annotations): `sql-string-concat` (JAVA-13), `no-dangerously-set-inner-html` (TS-10), `no-field-injection` (JAVA-3), `no-legacy-date-types` (JAVA-9), `slf4j-no-concat` (JAVA-12), `no-random-uuid-for-entity-ids` (JAVA-14, excluding `Ids.java`).
- **Running locally:** `docker run --rm -v "$PWD:/src" semgrep/semgrep semgrep --config .semgrep` (README and `coding-standards.md` updated to match). This avoids a Python install.
- **`.github/dependabot.yml`:** weekly updates for `maven` (`/backend`), `npm` (`/frontend`), `github-actions` (`/`), and `docker-compose` (`/`), with minor and patch updates grouped.
- **Supply chain:** third-party GitHub Actions are pinned by commit SHA with a version comment, and Dependabot keeps them current.

## 9. CI (M0-12) and repository settings

**`.github/workflows/ci.yml`** (push and PR to `main`), as parallel jobs:
1. **backend:** `setup-java` (Temurin 25, Maven cache), then `./mvnw -B verify`. This runs unit tests, Testcontainers integration tests, `ModularityTests`, `OpenApiContractTest`, and `spotless:check`. Docker is available on `ubuntu-latest`.
2. **frontend:** `setup-node` (from `.nvmrc`, npm cache), then `npm ci`, `lint`, `format:check`, `typecheck`, `test:coverage`, `build`.

Both the backend and frontend jobs append a coverage table to `$GITHUB_STEP_SUMMARY` (from JaCoCo's CSV and Vitest's `json-summary`, using a short inline script rather than a third-party action) and upload the HTML reports as artifacts.
3. **api-client:** `npm run gen:api`, then `git diff --exit-code src/shared/api`. This fails if the committed client is stale.

**Manual repository settings** (a checklist task, done once on GitHub): enable Dependabot alerts and security updates. Set the code scanning failure threshold to "High or higher" for security and "Errors" for others. Protect `main`: require a PR and the checks `backend`, `frontend`, `api-client`, `semgrep`, `gitleaks`, and `CodeQL`.
